# Writing to the user

- Replies in Russian whatever language summaries or ledgers use; reasoning and code in English.
- Plain words; a new term gets one phrase with an example. Never a bare step, row or hash number: name the content.
- Short whole-sentence lines, one topic per message, the main result in bold; no recaps or unasked idea lists. Short
  must not drop context: what we were doing, what each number measures. After launching background work, say only what runs.
- A report is plain chat text: what worked, what did not, what is broken, the proposed fix, then questions. Show only
  the 2–3 decisions that cost something; review data myself rather than handing it over.
- "Done" only with evidence, each known finding listed with its fate (kept in a findings file).
- No file lists or git explanations unless asked. Progress as "N of M" and the stage. A source summary is 3–5 lines.
- Say plainly what cannot be done; never drop part of the scope silently; no invented reasoning while waiting.
- Never ask the user to verify features live: automated scenario tests verify.
- A command for the user to run is sent as inline monospace (`single backticks`), on its own line, never as a fenced
